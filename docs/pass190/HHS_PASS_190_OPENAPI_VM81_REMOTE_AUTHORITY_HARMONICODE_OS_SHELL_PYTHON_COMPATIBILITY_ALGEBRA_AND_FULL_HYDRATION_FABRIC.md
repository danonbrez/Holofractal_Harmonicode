# 5. Architectural doctrine

The mandatory architecture is:

```text

                            ↓
                    hydration adapter
                            ↓
              canonical operation resolution
                            ↓
               typed HARMONICODE constructor
                            ↓
        CST → AST → typed operation graph → HIR → VMIR
```

“Direct connection to VM81” means that one governed API or local adapter invokes the singleton runtime authority without a second semantic engine. It SHALL NOT mean public access to raw memory, unvalidated register mutation, direct commit bypass, or a second route-owned VM81 instance.

# 21. Hydration modulus and membrane preservation

The inherited canonical probabilistic hydration expression SHALL remain preserved exactly:

```text
(List(x*Factorial(72),(y*(1/Factorial(72))))*z)*(w*List((y*(1/Factorial(72))),x*Factorial(72)))/u^72==(x*y)/(x*y)==u^72
```

Requirements:

1. Both scalar `List(...)` operands are exact byte-aligned circuit encodings.
2. Element order, lexical width, leading zeros, repetition, and position SHALL NOT be normalized away.
3. `1/Factorial(72)` SHALL remain an exact reciprocal encoding and SHALL NOT be reinterpreted as an ordinary modular inverse.
4. The maximum outer hydrated-state modulus is `1,259,713` unless a later explicit contract changes it.
5. Each nested parenthetical membrane at depth `n` retains its non-destructive boundary witness `() = n MOD (n+1)`.
6. The global modulus applies only at the outer hydrated-state envelope unless an operation contract explicitly authorizes local reduction.
7. Hydration adapters SHALL preserve the exact interior expression before applying witnesses or envelopes.
