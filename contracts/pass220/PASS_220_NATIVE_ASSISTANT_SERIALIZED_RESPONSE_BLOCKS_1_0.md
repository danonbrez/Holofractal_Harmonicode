# Pass 220 — Native Assistant Serialized Response Block Contract 1.0

**Status:** ADDITIVE / DEPLOYMENT-FACING / PLAIN-ENGLISH-EGRESS / HASH72+SHA256-CHAINED  
**Date:** 2026-09-27  
**Repository:** `danonbrez/Holofractal_Harmonicode`

## 1. Purpose

The native assistant SHALL treat the causal model's per-call generation limit as a
bounded generation buffer, not as the maximum length of a complete assistant
answer.

Long answers SHALL be constructible as an ordered sequence of generated payload
blocks with embedded provenance delimiters.

## 2. Canonical stream and human projection

For generated payload blocks `B_i` and delimiters `D_i`:

```text
SerializedResponse = B0 || D0 || B1 || D1 || ... || Bn || Dn
HumanResponse      = B0 || B1 || ... || Bn
```

The delimiters are not deleted from the canonical serialized response. The
human interface renders the payload projection while provider metadata retains
the full serialized stream.

## 3. Generated-token integrity

Once a native causal generation call returns decoded response payload, the
response-block serializer SHALL NOT trim, rewrite, normalize, censor, summarize,
or otherwise modify that generated payload before hashing and concatenation.

The serializer MAY issue a new continuation-generation request. New generated
continuation text is appended as new generated payload; previously generated
payload remains unchanged.

## 4. Embedded delimiter metadata

Each logical block delimiter SHALL bind at minimum:

- zero-based block index;
- SHA-256 of the exact UTF-8 payload bytes;
- chained Hash72 block receipt;
- prior block Hash72 receipt, when present;
- exact payload byte count;
- generated-token count accumulated into the logical block;
- generation-call count;
- terminal/nonterminal state.

The delimiter is framed by canonical record/unit separator characters and
remains embedded in `serialized_response`.

## 5. Ordering and tamper evidence

For each block:

```text
sha_i = SHA256(UTF8(B_i))
h72_i = Hash72(block_schema, index_i, sha_i, prev_h72_i, byte_count_i,
               token_count_i, call_count_i, terminal_i)
prev_h72_(i+1) = h72_i
```

Editing a payload, replacing a delimiter, reordering blocks, or breaking the
predecessor chain SHALL invalidate deterministic replay verification.

## 6. Payload-to-metadata ratio

For every admitted logical response block:

```text
payload_bytes >= 8 * delimiter_metadata_bytes
```

Equivalent framing:

```text
payload >= 8/9 of payload+metadata
metadata <= 1/9 of payload+metadata
```

A short generation result does not waive this invariant.

If a block has not reached the minimum payload ratio, the native assistant SHALL
continue generation before sealing the delimiter.

## 7. Productive continuation

Continuation used to satisfy the block ratio SHALL be generated by the same
native SOPHEON SiMSANE conversational generation path.

The internal continuation instruction directs generation toward substantive
material related to the user's request, including explanation, downstream
consequence simulation, ethical-invariant reasoning, concrete examples, or
implementation detail.

This is generated semantic continuation, not deterministic filler bytes and not
post-generation rewriting.

The continuation control itself is internal and SHALL NOT be emitted into the
user-facing answer or canonical payload.

## 8. Block-size buffer behavior

The default native causal generation buffer is raised from 256 to 1024 new
tokens per call.

The block stream MAY invoke the model repeatedly.

A model generation that consumes the complete per-call buffer is not interpreted
as whole-answer completion. The next witnessed block MAY continue the answer.

A generation ending before the buffer limit is a semantic-closure candidate,
but the current logical block still must satisfy the 8:1 payload/metadata ratio
before it can be sealed terminal.

## 9. Tool-bearing assistant turns

Governed tool execution SHALL NOT terminate the user-facing response at raw
receipt projection when the native causal model is available.

The flow SHALL be:

```text
original user request
-> governed tool calls
-> exact tool receipts/evidence
-> native causal synthesis
-> serialized response blocks
-> plain-English payload projection
-> provider invocation/ingress receipts
```

Tool receipts remain provenance evidence and SHALL be retained separately from
the conversational answer.

Nested textual tool payloads such as `content`, `text`, `answer`,
`message`, `summary`, `response`, or `result` SHALL remain available to
the synthesis path and SHALL NOT be reduced only to field/item counts.

## 10. Fallback behavior

If native causal generation is genuinely unavailable, the exact semantic
fallback remains permitted.

The fallback SHOULD surface nested textual tool payloads where present rather
than reporting only receipt structure.

Fallback evidence does not mint runtime or canonical authority.

## 11. Assistant ingress persistence

The governed assistant service SHALL preserve the native response-stream
manifest and canonical serialized response through provider-result ingress.

The ordinary assistant message `content` remains the human-readable payload
projection.

The provider invocation receipt binds the response-stream metadata as part of
the raw completion witness.

## 12. Authority boundary

This response-block stream has no authority to:

- mutate VM81;
- mint canonical Hash72 state;
- mint canonical Hash216 state;
- bypass the Pass 218/219 ethical membrane;
- promote generated narrative to external truth;
- convert tool/model output into canonical runtime state without normal ingress.

The Hash72 values generated here are response-order/provenance witnesses only.

## 13. Acceptance requirements

A conforming implementation SHALL demonstrate:

```text
RB-01 per-call generation limit behaves as a buffer rather than whole-answer cap
RB-02 exact generated payload is preserved without post-generation rewriting
RB-03 every block embeds SHA-256 + chained Hash72 delimiter metadata
RB-04 payload bytes are at least eight times delimiter bytes
RB-05 short payloads trigger generated semantic continuation until ratio closure
RB-06 a full buffer produces a nonterminal block and subsequent continuation
RB-07 block ordering and predecessor receipts are deterministic
RB-08 payload tampering fails stream verification
RB-09 nested tool text reaches final causal synthesis
RB-10 final assistant content is plain-English payload, not raw receipt projection
RB-11 canonical serialized stream remains available through assistant ingress
RB-12 inherited assistant modes and tool routing remain valid
```
