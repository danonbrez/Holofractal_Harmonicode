## 0. Ratification, purpose, and precedence

This document is the final normative Pass 151 implementation contract for the HHS internal language-processing layers.

Pass 151 exists to correct a structural failure found in ordinary linguistic-agent architectures:

\[
\boxed{\operatorname{ConstraintAvailable}\not\Rightarrow\operatorname{ConstraintEnforced}.}
\]

A model may correctly read, paraphrase, and discuss a specification while still violating it during tool use, implementation, testing, reporting, or artifact delivery. Pass 151 shall therefore separate:

1. verbatim contract preservation;
2. deterministic tool execution;
3. semantic problem solving;
4. Runtime-native validation;
5. evidence reconciliation;
6. terminal classification.

The architecture is deliberately asymmetric:

\[
\boxed{\text{Contract Executor executes;}\quad\text{Semantic Reasoner advises;}\quad\text{VM81 validates;}\quad\text{evidence closes.}}
\]

The Semantic Reasoner shall not own completion, implementation status, Runtime semantic authority, artifact truth, or terminal classification.

No generated report, wrapper, model output, test fixture, implementation comment, summary, or conversational interpretation may weaken a `SHALL`, `MUST`, `SHALL NOT`, or `MUST NOT` requirement in this contract or in any inherited authoritative contract.

Where thread context conflicts with an explicit current user specification, the explicit specification governs unless the user explicitly supersedes it.

## 3. Authority hierarchy

The authority order is fixed:

\[
\boxed{\begin{aligned}
\text{Explicit current user specification}
&>\text{ratified contract text}\\
&>\text{validated amendments}\\
&>\text{Runtime receipts and executed evidence}\\

### 3.1 Contract authority

The contract defines required work, prohibited substitutions, acceptance criteria, artifact obligations, and terminal states.

### 3.2 Contract Executor authority

The Contract Executor may inspect and modify authorized files, invoke compilers and tests, generate artifacts, collect receipts, update evidence status, and package the inherited nucleus.

### 3.4 Completion authority

Only the deterministic closure predicate over the obligation ledger and executed evidence may permit a completion classification.

\[
\boxed{\operatorname{ModelConfidence}\not\Rightarrow\operatorname{RequirementClosed}.}

### 6.1 Closure predicate

\[
\boxed{\operatorname{Closed}(r_i)=I_i\land R_i\land T_i\land E_i\land D_i}

### 6.2 Stub rule

\[
\operatorname{Stub}(a)\Rightarrow I_i=0.

Stub detection shall include constant placeholder returns, `TODO` or `NOT_IMPLEMENTED` paths, empty success paths, unreachable backing logic, mock-only storage, in-memory-only behavior where persistence is required, documentation-only declarations, and interfaces whose tests do not exercise required semantics.

### 6.3 Evidence monotonicity

Executed evidence is append-only. Later interpretation may attach errata but shall not erase earlier results.
