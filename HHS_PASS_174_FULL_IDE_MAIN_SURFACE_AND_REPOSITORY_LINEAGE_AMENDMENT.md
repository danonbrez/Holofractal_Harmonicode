# HHS PASS 174 — FULL IDE MAIN SURFACE AND REPOSITORY LINEAGE AMENDMENT

## Binding correction

The production root is a fully functioning integrated development environment. It is not a dashboard, documentation landing page, static demonstration, receipt viewer, validation-only console, or pass-history browser.

The default and dominant user workflow remains:

```text
PROJECT / FILE CREATION
→ FILE TREE + SOURCE EDITOR
→ MULTIMODAL FILE OR FOLDER INGRESS
→ APPLICATION / MEDIA PREVIEW
→ INTERPRETATION + MULTI-TARGET COMPILATION
→ VM81 EXECUTION + 5,184-BIT SNAPSHOT
→ RUNTIME REGISTRY + HUMAN-READABLE OUTPUT
→ PROJECT ZIP EGRESS
```

## Required main-surface capabilities

The public application SHALL visibly retain and operate all of the following on the primary workspace:

- project file tree with path-aware creation and folder-preserving import;
- editable multi-file source workspace and tabs;
- sandboxed browser application execution for project HTML, CSS, and JavaScript;
- native browser preview for image, audio, video, PDF, text, and preserved binary modalities;
- source-preserving multimodal ingress;
- selectable authorized compiler targets;
- bounded VM81 execution and exact 5,184-bit snapshots;
- live registered-object and runtime-service navigation;
- terminal, compiler output, application console, errors, receipts, and egress results;
- source, build, evidence, receipt, and manifest ZIP export.

Receipts and validation evidence support these workflows. They do not replace them.

## Complete repository inheritance surface

All repository-visible numbered pass contracts, specifications, amendments, implementation files, tests, workflows, reports, evidence, and receipts SHALL be projected into a searchable pass catalog.

All available authoritative-main commit history, including commits predating the numbered pass series, SHALL be reachable through a paginated commit-lineage service. A deployed checkout with `.git` uses local history. A Heroku slug without `.git` uses the public GitHub main-branch history API with bounded pages and caching behavior supplied by the HTTP layer.

Pass history and commit lineage are integrated IDE subsystems. They SHALL appear in the explorer and repository panel while leaving the editor, compiler, preview, VM81, registry, ingress, and egress as the dominant product surface.

## Visual correction

The Harmonicode Studio warm charcoal, amber, gold, compact-panel visual layer SHALL bootstrap independently from the main IDE module. A failure in project-lifecycle or application-workbench JavaScript SHALL NOT silently remove the global visual theme.

## Authority boundary

The application preview executes browser project code inside a sandbox without `allow-same-origin`. It is a development preview, not VM81 authority. Runtime mutation, compiler admission, Hash72/Hash216 evidence, VM snapshots, and governed egress remain backend-owned.

## Acceptance

Completion requires browser-visible proof that a user can create or import a project, edit multiple files, run its browser application or preview its media, invoke backend compilation and VM81 lifecycle operations, inspect registered objects and inherited repository constraints, and export the complete project archive without leaving the main IDE.
