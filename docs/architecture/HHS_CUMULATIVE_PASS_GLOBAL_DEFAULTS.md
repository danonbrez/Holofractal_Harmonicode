# HHS cumulative pass inheritance and global canonical defaults

## Repository-wide invariant

Every successfully validated numbered HHS pass is an additive upgrade to one cumulative HHS system image. A numbered pass is not a standalone application, one-off experiment, isolated native project, alternate runtime, or optional local feature.

A native_projects implementation may preserve the historical implementation nucleus, validation harness, benchmark, GUI, or application surface. It does not substitute for cumulative runtime exposure, canonical API/ABI registration, singleton VM81 authority integration, Hash72/Hash216 lineage, cumulative tests, and main incorporation.

If a successful implementation exists but cumulative exposure is absent, the repository classification is MISSING_CUMULATIVE_EXPOSURE and repair-forward is mandatory.

## Global canonical defaults

A successfully validated cross-cutting pass becomes the canonical default for every applicable inherited and future surface. This includes compression, latency reduction, caching and indexing acceleration, memory and serialization efficiency, security, cryptographic integrity, state validation, constraint enforcement, exactness enforcement, admission control, rollback protection, deterministic replay, data integrity, and authority separation.

These defaults are not opt-in and are not limited to the module that introduced them.

An older applicable surface that does not implement a later canonical default is WIRED_BUT_STALE and must be repaired forward. Historical age does not create a grandfather exemption.

Compatible defaults accumulate. They remain active until an explicit later upgrade or deprecation records the superseded mechanism, replacement, affected surfaces, migration impact, validation, regression coverage, authority integration, repository lineage, and main incorporation.

Silence, omission, refactoring, directory placement, or a new application does not deprecate a canonical default.

## Scope

Global means all applicable surfaces, not every surface regardless of type. A storage compression default applies to canonical storage paths; an admission or security default applies to every path capable of reaching the protected authority boundary.
