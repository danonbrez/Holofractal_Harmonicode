# HHS Pass 220 I078 — OpenAI Mathematics Corpus Extraction, Hydration, and Novelty Analysis

## Scope

I078 freezes the public `openai/math` release at immutable commit
`adc7f1241b42e322a6451854ab7e4b4c146bf78a` and hydrates metadata into a candidate-only HHS knowledge graph.

The extraction retains titles, family membership, immutable source identities,
formalization metadata, derived title-token relations, and three manually
inspected structural-overlap anchors. It does not retain manuscript bodies,
abstracts, PDF bytes, or copied Lean source bodies.

## Structural overlap anchors

### 1. 3 x 3 -> 9 x 9 symbolic tensor geometry

OpenAI family 172 was inspected at the Lean source level. The released code
uses an index `Fin 3 x Fin 3`, a 3 x 3 rational matrix, a 9 x 9 symbolic
polynomial matrix, a Kronecker/tensor evaluation, an explicit
`Fin 9 <-> Fin 3 x Fin 3` equivalence, and an exact 9 x 9 transported matrix
inside a rational-function/tensor-field construction.

This is retained as a structural-overlap candidate with the HHS 3 x 3 Lo Shu
nucleus, 9 x 9 / 81-cell geometry, and exact symbolic tensor machinery. No
lineage claim is minted by I078.

### 2. 72 as a 2/3-derived conductor boundary

OpenAI's Dirichlet-L Lean surface repeatedly uses the ideal generated by 72 in
character/conductor boundaries. One inspected theorem combines coprimality with
2 and 9 to establish coprimality with 72, and the reflection conductor nests 9
with a Q-times-72 factor.

This is retained as a structural-overlap candidate with HHS
`72 = 2^3 * 3^2`, the phase modulus, and the downstream 5184 geometry. Again,
I078 records correspondence only.

### 3. Tensor-power matrix multiplication

OpenAI family 107 uses finite coefficient tensors, tensor powers, polynomial
approximations, and matrix-multiplication tensor evaluation. It is tagged as
adjacent method overlap with HHS I075-I077 rather than as an exact constructor
match.

## Interpretation

The extraction answers the immediate research question positively at the
candidate-discovery level: the release is not merely a parallel collection of
the same matrix/tensor/modular structures already under discussion. It contains
a broad frontier of specialized theorems and constructions that should be
treated as potential new HHS training/proof material.

The correct next stage is deep hydration of the strongest novelty candidates:
parse theorem assumptions, conclusion types, proof dependencies, algebraic
objects, and executable/formal artifacts, then compare those semantic
structures against HHS constructors. Title/path overlap remains only the
first-pass routing signal.
