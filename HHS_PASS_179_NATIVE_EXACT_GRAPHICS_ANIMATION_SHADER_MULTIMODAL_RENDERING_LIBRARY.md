# 2. Normative language

The terms **SHALL**, **SHALL NOT**, **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are normative.

Pass 179 defines a reusable graphics library and rendering runtime. It SHALL NOT be reduced to a one-off demo, a JavaScript styling layer, a Three.js wrapper, a static shader collection, a detached preview page, or a decorative IDE background.

# 3. Governing invariant

The central Pass 179 invariant is:

```text
Authoritative graphics state is native, exact, deterministic, and VM81-governed.
JavaScript, Canvas, Three.js, WebGL, WebGPU, native GPU floating point,
and display-driver output are projection and presentation layers only.
```

The authoritative direction SHALL be one way:

```text
Harmonicode / VM81 state / asset source / visual editor operation
        ↓
byte-preserving ingress and typed validation
        ↓
exact native scene, animation, material, and compositor state
        ↓
VM81 admission membrane
        ↓
singular Hash72 ordered commit
        ↓
Hash216 scene/frame identities
        ↓
immutable native render-command buffer
        ↓
software, WebGPU, WebGL2, Three.js compatibility, or native GPU backend
        ↓
display / image / video / capture projection
```

No renderer-derived value may flow backward into authoritative state unless it is reintroduced as a new typed ingress candidate and independently admitted through the complete public authority path.

## 8.1 No-float authority

C `float`, C `double`, JavaScript `Number`, WGSL/GLSL floating-point values, GPU buffer floats, sampled texture values, and display output SHALL NOT become canonical graphics state.

Backends MAY use floating-point values after deterministic projection from admitted exact or fixed-point data. The projection function, scale, range, rounding mode, saturation behavior, and error bound SHALL be explicit and versioned.

## 8.2 Canonical quantization

At minimum, the implementation SHALL define canonical encodings for:

- 2D and 3D positions;
- scale and dimensions;
- rotation and quaternion orientation;
- normalized colors;
- opacity;
- depth;
- texture coordinates;
- animation time;
- camera parameters;
- particle state;
- lighting parameters;
- gradient stops;
- clipping and scissor rectangles.

Overflow SHALL reject, saturate, or widen according to a typed policy. Silent wraparound is forbidden.

## 8.3 Visual interpolation

Presentation interpolation MAY use backend floats, but it SHALL be marked `RENDER_ONLY_INTERPOLATION`, derived from two admitted frames, excluded from Hash72 transition authority, and forbidden from writing back into authoritative state.

# 10. Deterministic animation system

Animation SHALL use an exact fixed-step clock:

\[
t_n=t_0+n\Delta t,
\qquad n\in\mathbb Z_{\ge0}.
\]

The animation runtime SHALL provide:

- exact duration and frame indexing;
- keyframe, procedural, physics-driven, and state-machine tracks;
- linear, stepped, Hermite, cubic, spring-like, and harmonic phase curves expressed in exact or certified forms;
- animation layers and weighted blending;
- additive and override channels;
- event tracks;
- skeletal and sprite animation;
- camera animation;
- material and gradient animation;
- particle-emitter animation;
- timeline scrub, pause, single-step, reverse replay, and branch comparison;
- deterministic interruption and transition rules;
- replay receipts for every authoritative animation transition.

Any spring, damping, or easing function used authoritatively SHALL be represented through exact recurrence, fixed-point integration, symbolic form, or certified interval rules. Browser CSS transitions and JavaScript animation libraries MAY decorate non-authoritative interface elements but SHALL NOT define canonical application or scene motion.

# 14. Typed shader intermediate representation


The shader compiler SHALL:

2. reject undeclared side effects and unsafe external code;
3. compile deterministic backend projections such as WGSL and GLSL;
4. optionally compile native backend forms through the selected GPU adapter;
5. bind source identity, IR identity, compiler version, backend target, and generated shader identity;
6. cache only by complete identity;
7. produce diagnostics with source-to-generated provenance;
8. prevent shader compilation or execution from gaining VM81 or application-state authority.

Raw backend shader source MAY be available as an expert escape hatch only through an explicit untrusted projection profile. It SHALL be sandboxed, resource-bounded, visibly classified, and forbidden from authoritative state access.

# 16. GPU and browser backends

Exact authority SHALL not be weakened for speed.

The implementation SHALL use:

- instancing and batching;
- dirty-range updates;
- structural sharing;
- atlas and pipeline caching keyed by complete identity;

- adaptive rendering profiles that do not alter authoritative state;
- separation of simulation, animation, and presentation rates;
- worker or native-thread execution where safe;
- explicit backpressure;
- bounded queues and memory;
- GPU-context-loss recovery;
- restartable compilation and capture stages.

Representative acceptance targets SHALL include:

- stable 60 Hz presentation on a capable desktop for both golden scenes;
- stable 30 Hz or better mobile-safe presentation on the project’s supported mobile class;
- no recurring long-frame freeze during steady-state interaction;
- no unbounded resource growth during a ten-minute golden-scene run;
- no full scene or shader rebuild when a bounded incremental update is sufficient;
- separate measurements for native scene update, VM81 admission, Hash72/Hash216 overhead, command generation, backend translation, GPU execution, software rasterization, capture, and UI responsiveness.

Renderer FPS SHALL not be reported as simulation, VM81, or compiler throughput.
