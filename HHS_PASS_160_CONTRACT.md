```text

sealed transition membership   <= O(log m)
fast admission                 independent of total historical depth
```

where `m` is the containing segment size.

# 7. Normative authority separation

## 7.1 Semantic validation authority

Semantic validation proves that a transition was admissible when originally executed:

```text
T_i : S_(i-1) --[O_i, I_i, C_i]--> S_i
V_i_semantic = Admit(S_(i-1), O_i, I_i, C_i, S_i)
```

Only semantically validated transitions may enter the validated-transition store.

Ordinary fast reuse shall not reexecute the original operation.

## 7.2 Canonical identity authority

Canonical identity proves that the transition object has the inherited HHS identity assigned to its exact canonical serialization.

```text
V_i_identity = Hash216(CanonBound(T_i)) == H_i
```

## 7.3 Cryptographic storage-integrity authority

Storage-integrity verification proves that retrieved bytes match their cryptographic commitment:

```text
V_i_storage = SHA256(Canon(T_i)) == D_i
```

Storage verification does not repeat semantic execution.

## 7.4 Historical coverage authority

Historical coverage proves that every declared transition position belongs to a continuous authenticated range with required overlap, no gaps, and no unauthorized duplication.

## 7.5 Audit authority

Audit sampling tests stored objects, membership paths, overlaps, index mappings, and serialization stability.

An audit may confirm, quarantine, request repair, or revoke reuse eligibility. It may not create semantic authority for an unvalidated transition.

## 7.6 Runtime admission authority

Runtime admission establishes exact compatibility between a stored transition and the current parent receipt, parent state, operation, implementation, input, constraints, semantic root, registry root, and revocation state.

## 7.7 Commit authority

Only the existing outer VM81 or Pass 158 explicit transition-commit authority may convert a nested proposal into authoritative state.

# 19. Fibonacci-prime temporal coverage

## 19.1 Default profile

```text

L1: F13 * 11 = 233   * 11 = 2,563 timing buckets

```

The products are temporal cycle lengths, not segment sizes and not fixed index strides.

## 19.2 Exact operational mapping

For active domain length `N_l` and temporal cycle length `W_l`, timing bucket `b` assigns:

```text
q_l(b) = floor(((b + 1) * N_l) / W_l)
       - floor((b * N_l) / W_l)
```

samples from the next positions of the level's keyed coverage permutation.

For `b = 0 ... W_l - 1`:

```text
sum q_l(b) = N_l
```

Therefore one temporal cycle visits every active level index exactly once while distributing the work over exactly `W_l` fixed-work buckets.

Mandatory boundary checks are additional and do not advance the unique coverage cursor when they duplicate a scheduled index.

# 20. Cryptographic coverage permutation

## 20.1 Authoritative permutation

The authoritative audit order shall use a keyed cryptographic permutation, not a fixed stride and not the affine map as the sole secrecy mechanism.

The interoperable baseline is a four-round HMAC-SHA-256 Feistel permutation over the smallest even-bit domain covering `N`, with cycle walking for values outside `[0, N)`.

Required properties:

- deterministic replay;
- secret-key unpredictability before reveal;
- bijection over the active domain;
- every index exactly once;
- no repeats before cycle completion;
- canonical cross-language encoding;
- independent test vectors.

## 20.2 Affine reference permutation

The map:

```text
pi_ref(k) = (a * k + b) mod N, gcd(a, N) = 1
```

may be retained as a mathematical coverage reference and test oracle. It proves complete positional coverage but shall not be the authoritative unpredictability mechanism after partial schedule observation.
